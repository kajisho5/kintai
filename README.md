# Kintai

勤怠管理システム。CYBER XEED など既存製品を調査し（[docs/competitor-research.md](docs/competitor-research.md)）、
小規模企業向け・セルフホスト可能な代替を目指しています。

![ダッシュボード](docs/screenshots/dashboard.png)

## できること

- **打刻**（出勤・退勤・休憩）— 時刻は端末ではなくサーバーが記録します
- **ダッシュボード**（管理者）— 全社員の本日の勤務を運行ダイヤのように一覧。36協定の月末見込、承認待ち
- **勤怠一覧・個人明細**（月次、CSV出力）— 日8時間／週40時間超の時間外、深夜、法定休日、打刻漏れの検出
- **36協定チェック** — 月45時間・年360時間、特別条項（年720時間・年6回）、単月100時間未満、2〜6か月平均80時間
- **申請・承認** — 残業・休日出勤・有給・打刻修正。承認すると有給は取得日として登録、打刻修正は勤怠に反映
- **有給管理** — 付与日数（通常・比例）、残日数、年5日の取得義務
- **認証と権限** — 管理者／一般社員。一般社員は自分の勤怠・申請・有給だけ

## 構成

| パス | 内容 |
|---|---|
| `src/engine` | 労働時間の計算エンジン（日次／週／月、36協定、有給付与）。DB・UI非依存の純関数 |
| `src/domain` | 打刻データから月次・リスク・本日の状況を組み立てる集計層（サーバーと画面で型を共有） |
| `src/server` | API サーバー（Hono + SQLite）。認証、打刻、勤怠、申請、有給 |
| `src/app` | 画面（React + Vite） |

## 使い方

Node.js 22.13 以上が必要です（SQLite は組み込みの `node:sqlite` を使います）。

```bash
npm install

# デモデータ入りの DB を作る（開発・試用向け。本番では実行しないでください）
SEED_PASSWORD='8文字以上のパスワード' npm run db:seed      # 既定: data/kintai.db

# 開発（2つのターミナル）
npm run dev:server        # API  http://127.0.0.1:8787
npm run dev               # 画面 http://localhost:5173（/api を 8787 に中継）

# 本番相当（画面もAPIサーバーから配信）
npm run build
npm start                 # http://127.0.0.1:8787
```

デモデータのログイン: 管理者 `e16`（山口 恵）、一般社員 `e01`〜`e18`。パスワードは `SEED_PASSWORD`（未指定なら `kintai-demo`）。
社員・勤務実績はすべて生成したサンプルで、実在の人物・企業とは無関係です。

### 環境変数

| 変数 | 既定 | 内容 |
|---|---|---|
| `PORT` / `HOST` | `8787` / `127.0.0.1` | 待ち受け。外部公開する場合はリバースプロキシ（HTTPS）の背後に置いてください |
| `KINTAI_DB` | `data/kintai.db` | SQLite ファイル |
| `KINTAI_TZ` | `Asia/Tokyo` | 会社のタイムゾーン（日付の切り替わりと打刻時刻に使用） |
| `KINTAI_SECURE_COOKIE` | （未設定） | `1` で Cookie に Secure を付ける。HTTPS で運用するときは必須 |

## セキュリティの方針

- パスワードは scrypt でハッシュ化して保存。同じ社員IDで5回続けて失敗すると5分ロック
- セッションは HttpOnly / SameSite=Lax の Cookie。トークンは DB にハッシュで保存し、パスワード変更で他端末を無効化
- 更新系 API は別オリジンからのリクエストを拒否。CSP などのヘッダーを付与
- 打刻・修正・承認・ログインの結果は `audit_log` に記録。打刻は追記のみで、修正は修正イベントの追加で行う
- 自分の申請は承認できない（承認者と申請者の分離）

## 現状の制約

- **社員の追加・退職・権限変更の画面は未実装**です（DB を直接編集します）。祝日・特別条項の有無の設定画面もありません
- 日をまたぐ勤務（夜勤）は未対応です。打刻は日付ごとに集計します
- 変形労働時間制・フレックスの精算期間・端数処理・給与ソフト連携は未実装です
- 祝日は2026年分のみ登録しています
- ログインの失敗回数はメモリ保持のため、サーバー再起動で消えます。複数台構成にも対応していません
- 労働基準法に関する数値（付与日数表、36協定上限など）は実運用前に社労士等による確認が必要です
