# セキュリティ自己点検の結果

**位置づけ**: このシステムを作った側（AI）が手配した、**自己点検**です。第三者による脆弱性診断（侵入テスト）の代わりにはなりません。公開前に、外部の専門家による診断を受けてください。また、労働時間の計算、規約・プライバシーポリシーの法的な確認は、社会保険労務士・弁護士の業務で、この点検には含まれません（確認してほしい点は [labor-rules-review.md](labor-rules-review.md)）。

**方法**: 書いた担当とは別の3つの診断担当が、ローカルで起動したサーバー（127.0.0.1）と、メモリ上のテスト用アプリに対して、実際に攻撃を試みました。外部への通信、他者のシステムへの攻撃はしていません。再現できたものだけを指摘として扱い、再現できなかったものは「確認した範囲」に残しています。

- 認証・セッション・アカウント（ログイン、セッション、CSRF、パスワード再設定、メール確認、二段階認証、共用端末）
- 認可・テナント分離（全エンドポイント × ロールの表、IDOR、書き込み制限の迂回、課金、集計の使い回し、入力検証）
- 注入・秘密情報・依存関係・配備（SQL・XSS・CSV・メール、Git履歴、npm audit、Docker・Caddy、サービス拒否）

**結論**: 致命的・高の脆弱性（一般社員から管理者への昇格、他の会社のデータの読み書き、書き込み制限の迂回、課金の迂回、SQL・XSS・CSV数式の注入、パストラバーサル、秘密情報の混入）は、再現できませんでした。`npm audit` は、本番依存（46）・開発依存（115）とも 0 件でした。再現できたのは、可用性（サービス拒否）、メールの悪用、アカウントの締め出しなどでした。

## 再現できた指摘と対応

| 重大度 | 指摘 | 対応 |
|---|---|---|
| 中〜高 | 認証済みの管理者が、巨大なCSV取り込みで、全社のリクエストを数秒止められる（解析が同期処理） | 修正: 解析前の行数・列数の確認、本文・CSVの上限を下げた（1MB / 80万文字）、会社ごとの回数制限 |
| 中 | 重いパスワード計算を、管理者が無制限に呼べる（他社のログインが遅くなる） | 修正: 会社ごとの回数制限、一時パスワードは軽いコストで保存（ログイン時に作り直す） |
| 中 | パスワード再設定メールの増幅（同じ宛先の社員を多数登録して、1回の申請で多数送れる）、会社を増やして宛先ごとの上限を回避 | 修正: 1回の申請で1通まで、同じメールアドレスの社員の重複登録を禁止、同じ宛先へ全社で1時間6回 |
| 中 | 登録後の氏名変更で、案内メールの「URL・改行禁止」を回避できる（任意の宛先に、攻撃者の文面） | 修正: 氏名・部署・役職・会社名の全経路で、URL・短縮URL・ドメイン名・全角を拒否。送り先を変えた再送では、入力した氏名を本文に入れない |
| 中 | 確認メールの再送が、宛先ごとの上限の対象外（他人のアドレスに、繰り返し送れる） | 修正: 再送も、登録と同じ「同じアドレス宛 24時間3通」に数える |
| 中 | 他人が失敗を重ねて、管理者のログインをロックできる（アカウント単位の20回で15分）。失敗の回数が時間で減らない | 修正: 前にログインに成功した端末は、ロック中でも、パスワードの確認に進める。失敗の回数は30分で忘れる。**新しい端末は、最長15分入れない（残る）** |
| 低〜中 | 共用端末の暗証番号の入力枠（端末あたり60回/10分）を、成功も数えるため、朝の打刻で枯渇する | 修正: 成功は数えない |
| 低 | セッションだけで二段階認証を登録でき、本人を締め出せる | 修正: 設定を始めるときに、パスワードの再入力が必要（総当たりは制限） |
| 低 | 再設定リンクが、パスワード変更・管理者の再発行・退職のあとも有効 | 修正: これらで、発行済みのリンクを無効にする |
| 低 | 未認証で、任意の文字列を、他社の操作記録に書き込める | 修正: 存在しない社員IDは、操作者として記録しない |
| 低 | `X-Forwarded-For` の先頭を信頼するため、追記型のプロキシの背後では、IP単位の制限を回避できる | 修正: 右端を使う。運用資料に、プロキシの条件を明記 |
| 低 | `SECRET_KEY` が空でも本番で起動し、二段階認証の秘密鍵が平文で保存される | 修正: 本番では、32文字以上が無いと起動しない |
| 低 | scrypt のコストが低い（N=2^14）、パラメータがハッシュに入っていない | 修正: N=2^15、パラメータをハッシュ文字列に入れ、ログイン時に古い形式を作り直す |
| 低 | 不正な `Origin`（`null` など）で 500 になる。CSP に base-uri・form-action・object-src がない | 修正: 403 にする。`Sec-Fetch-Site: cross-site` も拒否。CSPを追加 |
| 低 | 存在しない `/app/assets/…` が、HTMLを1年キャッシュ可能な形で返す | 修正: 404 |
| 低 | データ・バックアップのファイルの権限が 0644、コンテナ内のアプリのコードが書き込み可能 | 修正: 0600 / 0700、コードは root 所有、`no-new-privileges`・`cap_drop: ALL` |
| 低 | 入社日に極端な日付（9999年）を入れると、会社全体の有給の画面が 500 になる | 修正: 1950〜2100年に限る |
| 低 | 座席数（課金の数量）の同期が、並列に送られ、古い人数が最後に残りうる | 修正: 会社ごとに直列、重なった要求は最新の人数で1回 |
| 低 | 運用コマンドで `past_due` にすると、猶予期間の起点がなく、書き込めたままになる | 修正: 起点を設定 |

## 残っているもの（対応していない・設計上の判断）

- **メールの悪用**: IPを多数使い、別々のアドレスへ少しずつ送る攻撃は防げません。逆に、他人のアドレスで3回登録を試みて、その本人の登録を24時間止めること、全体の枠（1時間300通）を使い切って新規登録を止めることができます。SPF・DKIM・DMARC、CAPTCHAを検討してください。
- **新しい端末からのログイン**: アカウント全体のロック中は、最長15分入れません。
- **管理者の権限の強さ**: 管理者は、他の管理者のパスワード・二段階認証を、第二要素なしで再発行・解除できます。管理者が2人いると、片方を降格して、自分の修正申請を承認できます（操作記録には残る）。
- **共用端末の暗証番号（6桁）・カード番号**: 内部者による総当たり、DB流出時のオフラインでの割り出しに弱い。
- **メール未確認の会社の放置**（自動削除なし）、**監査ログの保管期間**、**パスワードの強度検査**、**成功するログインの回数制限**、**打刻端末のURLによる端末の入れ替え**。
- **ファイルディスクリプタ**: 会社を大量に作られた場合に、上限が小さい環境では、新規登録が失敗します。
- **未検証**: Caddy・Docker は起動できていません（設定ファイルの読解のみ）。Stripe の実接続も未検証です。

詳しい運用上の注意は、[operations.md の §8](operations.md) を参照してください。
